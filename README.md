# IMS Weather API

[![Docker Pulls](https://img.shields.io/docker/pulls/techblog/ims-api)](https://hub.docker.com/r/techblog/ims-api)
[![Docker Image Version](https://img.shields.io/docker/v/techblog/ims-api?sort=date)](https://hub.docker.com/r/techblog/ims-api/tags)

A small [FastAPI](https://fastapi.tiangolo.com/) service that exposes weather data from the
**Israel Meteorological Service (IMS)** as a simple REST API. It wraps the
[py-weatheril](https://github.com/t0mer/py-weatheril) Python package (`weatheril` on PyPI), which reads
the public JSON feeds behind [ims.gov.il](https://ims.gov.il).

Use it when you want IMS current conditions and 5-day forecasts over HTTP, for example from Home
Assistant, n8n, Node-RED, dashboards, or scripts that can't import a Python library directly.

> **Unofficial project.** This service is not affiliated with, endorsed by, or supported by the
> Israel Meteorological Service. All weather data belongs to IMS.

## Features

- Current weather analysis for a location: temperature, feels-like, humidity, rain and rain chance,
  wind speed, direction and gusts, UV index, PM10, wave height, daily min/max, and the raw IMS
  record.
- 5-day forecast with daily summaries (min/max temperature, max UVI, weather description, national
  forecast text) and per-hour temperature and weather.
- Hebrew (`he`, default) or English (`en`) output for descriptions and names.
- A built-in list of 163 IMS location IDs: 84 cities and towns, 73 national parks and tourist
  sites, and 6 additional locations.
- Interactive OpenAPI docs (Swagger UI and ReDoc) generated by FastAPI.
- A `/health` endpoint for container health checks.
- A prebuilt multi-arch Docker image (`linux/amd64`, `linux/arm64`) on Docker Hub.

## How it works

```mermaid
flowchart LR
    C[HTTP client] -->|GET /weather/...| A[ims-api<br/>FastAPI + uvicorn :8000]
    A -->|weatheril.WeatherIL| W[py-weatheril]
    W -->|HTTPS JSON| I[ims.gov.il<br/>now_analysis / full_forecast_data]
```

1. The request's `location_id` is checked against the built-in location list.
2. A `WeatherIL(location_id, language)` object is created and calls IMS
   (`https://ims.gov.il/{language}/now_analysis/{location}` for current weather,
   `https://ims.gov.il/{language}/full_forecast_data/{location}` for the forecast).
3. The returned objects are converted to JSON and sent back.

The service stores nothing. Every request fetches fresh data from IMS.

## Requirements

- **Docker** (recommended), or **Python 3.11** (the version used by the Docker image) with `pip`.
- Outbound HTTPS access to `ims.gov.il`. py-weatheril turns off IPv6 for its requests, so the host
  needs working IPv4.
- No API key or account is needed.

## Installation

### Docker

The image is published on Docker Hub as
[`techblog/ims-api`](https://hub.docker.com/r/techblog/ims-api) for `linux/amd64` and `linux/arm64`.

```bash
docker run -d --name ims-api -p 8000:8000 --restart unless-stopped techblog/ims-api:latest
```

The API is then available at `http://localhost:8000`.

### Docker Compose

```yaml
services:
  ims-api:
    image: techblog/ims-api:latest
    container_name: ims-api
    ports:
      - "8000:8000"
    restart: unless-stopped
```

```bash
docker compose up -d
```

```bash
git clone https://github.com/t0mer/ims-api.git
```

```bash
source .venv/bin/activate

uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Configuration

The application reads **no environment variables** and has no config file. The only settings are
the uvicorn options on the command line:

| Setting | Where | Default | Description |
|---|---|---|---|
| Listen host | `--host` in the Dockerfile `CMD` / uvicorn command | `0.0.0.0` | Interface uvicorn binds to. |
| Listen port | `--port` in the Dockerfile `CMD` / uvicorn command | `8000` | Port inside the container. To use another port on the host, change the mapping, e.g. `-p 8080:8000`. |
| `PYTHONPATH` | `docker-compose.yml` | `/app` | Set by the repository's Compose file. The app does not need it, because the image already runs from `/app`. |

Per-request options (location and language) are passed as API parameters, described below.

## API reference

Base URL: `http://<host>:8000`. All endpoints are `GET`, need no authentication, and return JSON.

Interactive documentation is served by FastAPI:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- OpenAPI schema: `http://localhost:8000/openapi.json`

| Method | Path | Description |
|---|---|---|
| `GET` | `/` | Service info. |
| `GET` | `/locations` | All supported location IDs and their Hebrew names. |
| `GET` | `/weather/current/{location_id}` | Current weather analysis for a location. |
| `GET` | `/weather/forecast/{location_id}` | 5-day forecast with hourly data. |
| `GET` | `/health` | Health check. |

### Common parameters

| Parameter | In | Type | Default | Description |
|---|---|---|---|---|
| `location_id` | path | int | required | An IMS location ID from [`/locations`](#get-locations). Unknown IDs are rejected. |
| `language` | query | string | `he` | `he` (Hebrew) or `en` (English). The value is passed straight to IMS and is not validated, so use only these two. |

### `GET /`

```bash
curl http://localhost:8000/
```

```json
{
  "message": "IMS Weather API",
  "description": "FastAPI wrapper for py-weatheril",
  "docs": "/docs",
  "version": "1.0.0"
}
```

### `GET /locations`

Returns the built-in location map. JSON object keys are strings, and names are always in Hebrew
(this endpoint takes no `language` parameter).

```bash
curl http://localhost:8000/locations
```

```json
{
  "locations": {
    "1": "ירושלים",
    "2": "תל-אביב, חוף",
    "3": "חיפה",
    "...": "...",
    "707": "חצבה"
  }
}
```

### `GET /weather/current/{location_id}`

Returns the current IMS analysis for one location, wrapped in a `data` object. The fields are the
attributes of py-weatheril's `Weather` object. `json` holds the raw IMS record.

```bash
curl "http://localhost:8000/weather/current/2?language=en"
```

Example response (values are illustrative):

```json
{
  "data": {
    "language": "en",
    "lid": "2",
    "humidity": 65,
    "rain": 0.0,
    "rain_chance": 0,
    "temperature": 27.4,
    "due_point_temp": 20,
    "wind_speed": 12,
    "wind_chill": 27,
    "wind_direction_id": 13,
    "feels_like": 28.9,
    "heat_stress_level": 1,
    "forecast_time": "2026-09-29T12:00:00+03:00",
    "u_v_index": 7,
    "u_v_level": "H",
    "u_v_i_max": 8,
    "u_v_i_factor": 0.9,
    "min_temp": 23,
    "max_temp": 30,
    "pm10": 40,
    "json": { "lid": "2", "temperature": "27.4", "...": "raw IMS fields" },
    "weather_code": 1250,
    "wave_height": 0.6,
    "gust_speed": 25,
    "modified_at": "2026-09-29T12:05:00+03:00",
    "location": "Tel Aviv Coast",
    "description": "Clear",
    "wind_direction": 270
  }
}
```

Field names come from py-weatheril (including its spelling, e.g. `due_point_temp`). Units follow
IMS: temperatures in °C, rain in mm, wind speed in km/h, wave height in metres.
`wind_direction_id` is the IMS wind direction code (1–16), and `wind_direction` is that code
converted to an azimuth in degrees (`-1` when unknown).

### `GET /weather/forecast/{location_id}`

Returns one entry per forecast day, each with hourly data.

```bash
curl "http://localhost:8000/weather/forecast/1?language=en"
```

Example response (values are illustrative, trimmed to one day and two hours):

```json
{
  "days": [
    {
      "date": "2026-09-29T00:00:00+03:00",
      "location": "Jerusalem",
      "day": "Tuesday",
      "weather": "Clear",
      "minimum_temperature": 18,
      "maximum_temperature": 27,
      "maximum_uvi": 8,
      "description": "Fair to partly cloudy. No significant change in temperatures.",
      "hours": [
        { "hour": "07:00", "weather": "Clear", "temperature": 19 },
        { "hour": "08:00", "weather": "Clear", "temperature": 21 }
      ]
    }
  ]
}
```

- `date` is an ISO 8601 timestamp for midnight (Asia/Jerusalem) of that day.
- `day` is the weekday name, in Hebrew when `language=he`.
- `description` is the IMS national forecast text for that day.
- `hours` includes only `hour`, `weather`, and `temperature`. Other hourly fields that py-weatheril
  provides (humidity, rain chance, wind, UV, and so on) are not exposed.

### `GET /health`

```bash
curl http://localhost:8000/health
```

```json
{ "status": "healthy", "service": "ims-api" }
```

This only shows that the web server is running. It does not check that IMS is reachable.

### Errors

Errors use FastAPI's standard format:

```json
{ "detail": "..." }
```

| Status | When |
|---|---|
| `422` | `location_id` is not an integer (FastAPI validation). |
| `500` | Any error while fetching or converting IMS data. Because the handlers catch every exception, an unknown `location_id` also returns `500`, with `"detail": "400: Invalid location ID"`. |

## Location IDs

Common IDs:

| ID | Hebrew name | English |
|---|---|---|
| 1 | ירושלים | Jerusalem |
| 2 | תל-אביב, חוף | Tel Aviv, Coast |
| 3 | חיפה | Haifa |
| 8 | באר שבע | Beer Sheva |
| 21 | רעננה | Ra'anana |
| 31 | אילת | Eilat |
| 50 | צפת | Safed |
| 84 | תל אביב-יפו | Tel Aviv-Yafo |
| 267 | מצדה | Masada |

The IDs fall into three ranges:

- `1`–`84`: cities and towns
- `200`–`278`: national parks and tourist sites (some numbers in the range are unused)
- `702`–`707`: additional locations

Call [`/locations`](#get-locations) for the full list. The list is hard-coded in `app/main.py` and
was taken from the IMS locations list (`https://ims.gov.il/he/locations_info`).

## Data source and terms of use

All weather data comes from the **Israel Meteorological Service** ([ims.gov.il](https://ims.gov.il))
through the public JSON endpoints that its website uses. These are not a documented public API and
may change without notice.

- This project and py-weatheril are **unofficial** and not affiliated with IMS.
- The data belongs to IMS. Review the terms of use on [ims.gov.il](https://ims.gov.il) before
  redistributing it or using it commercially, and credit IMS as the source.

- Be considerate: every API call makes at least one request to ims.gov.il. Put a cache in front of
  the service if many clients poll it.

## Security notes

- The API has **no authentication** and no rate limiting. Run it on a trusted network, or put it
  behind a reverse proxy that adds authentication, TLS, and rate limits before you expose it to the
  internet.
- Every request is forwarded to ims.gov.il, so an exposed instance can be used to generate traffic
  to IMS.
- `500` responses include the raw exception text in `detail`, which can reveal internal details.
- The container runs as root (the Dockerfile has no `USER` line), and `requirements.txt` does not
  pin versions, so each image build may pull different dependency versions.

## Troubleshooting

- **`500` with `"detail": "400: Invalid location ID"`**: the `location_id` is not in the built-in
  list. Check [`/locations`](#get-locations).
- **`/weather/current` returns `200` but most fields are `null`**: py-weatheril returned no data
  for the location (for example, IMS has no current analysis for that site, or the request to IMS
  failed). The service then falls back to a fixed set of keys (`location`, `humidity`, `rain`,
  `temperature`, `wind_speed`, `feels_like`, `uv`, `time`, `json_result`), all `null`. Check the
  container logs for errors from py-weatheril.
- **`/weather/forecast` returns `500` with `'NoneType' object has no attribute 'days'`**:
  py-weatheril could not fetch or parse the IMS forecast. Check that the host can reach
  `https://ims.gov.il` over IPv4.
- **Names or descriptions are in the wrong language**: py-weatheril caches location names and weather
  descriptions per process, in the language of the **first** request after
  startup. Mixing `he` and `en` in one running instance can return names in the first language.
  Run one instance per language, or restart the container, if this matters.
- **`docker compose up` fails with a YAML error, or the container shows as unhealthy**: see the
  note under [Docker Compose](#docker-compose).
- **Requests hang or time out**: IMS may be slow or unreachable from your network. py-weatheril
  uses IPv4 only.

### CI / image publishing

Both workflows run only on manual dispatch (`workflow_dispatch`):

| Workflow | Image | Platforms | Tags |
|---|---|---|---|
| `docker-image.yml` ("Docker Build") | `techblog/ims-api` (Docker Hub) | `linux/amd64`, `linux/arm64` | `latest` and the short commit SHA (checkout uses the default shallow clone, so git tags are never fetched and `git describe` always falls back to the SHA) |
| `publish-ghcr.yml` ("Publish to GHCR") | `ghcr.io/t0mer/ims-api` | `linux/amd64`, `linux/arm64`, `linux/arm/v7` | the `tag` input (default `latest`) and `latest` |

The Docker Hub workflow needs the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` repository secrets. The
GHCR workflow uses the built-in `GITHUB_TOKEN`.

As of this writing, Docker Hub has the `latest` and `dc55825` tags. The GHCR workflow has not
published an image yet, and there are no GitHub releases.
